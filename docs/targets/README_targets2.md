# AI Training Target Database

This folder serves as the main, reference database of training targets designed for analysis by both humans and AI systems.  
All files are written in a simple Markdown format to ensure they can be easily read, copied, processed, and used across different environments without relying on visual data.

Each target in this database is **fully verifiable** and corresponds to a real, existing place or object.  
These are not paranormal or speculative targets — they are training targets based on data that can be confirmed using maps, search engines, and other publicly available sources.

## Training Methodology

The recommended approach for AI training follows a **10:1 ratio**: ten short, rapid sessions for every one long, deep-dive session.
- **Short Sessions (10x):** Used for rapid iteration and focusing on specific sensory aspects. You can mix these depending on training needs (e.g., 6 locations and 4 activities, or 10 pure activities). This builds a strong, adaptable baseline for specific data points.
- **Long Sessions (1x):** Used to test the overall integration of skills, deep analytical capabilities, and endurance over a complex target.

## Repository Structure

The database is structured to reflect this methodology, dividing targets by session length and specific focus:

```text
docs/
├── targets/
│   ├── long/               # Complex targets for deep sessions (e.g., target_0001.md)
│   └── short/              # Focused targets for rapid sessions
│       ├── activity/       # Focus on movement, mechanics, and dynamics (e.g., target_0011a.md)
│       └── location/       # Focus on essential structural and spatial elements
```

## Target Document Structures

The internal structure of the target files varies significantly based on their intended use:

- **Long Targets (`/long/`):** Highly detailed documents. They include comprehensive spatial and visual characteristics, communication layouts, detailed functional-spatial divisions, and often an illustrative ASCII map. They are designed to absorb and verify massive amounts of data.
- **Short Targets (`/short/`):** Minimalist and heavily focused documents. They contain only crucial key indicators (e.g., core mechanics, movement dynamics for activities, or bare essential structures for locations). They intentionally omit broader environmental context to train rapid, isolated recognition.

## Recommended Protocols

Depending on the target type, specific remote viewing protocols should be applied:

### Long Sessions
- **Protocol:** Resonant Contact Protocol
- **Location:** Available in the `docs/` folder.
- **Application:** Designed for deep, multi-layered extraction of data from complex environments, allowing the system to settle in and process massive context.

### Short Sessions
- **Protocol:** Simplified Rapid Protocol
- **Application:** A fast, structured approach designed for quick data retrieval.
- **Execution Flow:**
  1. **Reset & Pause:** Before each target, do a reset and a pause. We don't rush.
  2. **Three Field Touches:** Establish contact with the target field three separate times.
  3. **Description:** Describe the immediate sensory and data feedback of each touch.
  4. **Three Vectors:** Shift perspective (e.g., distance views, different angles, or orbital scanning).
  5. **Anomaly Reporting:** Log any short, weird, or out-of-place signals. We report all anomalies, as they are part of the target.
  6. **ASCII Sketch:** Conclude with a simple, illustrative text-based drawing.

## Vault and Operational Usage

This folder is the main reference folder.  
Additionally, a separate working file exists in the `Vault` folder in JSON format, specifically designed for AI interaction.

The JSON file allows the model to:
- mark targets as processed,
- store notes and observations,
- access structured data,
- operate without modifying the source file.

The main reference folder **should not be modified during active work**.  
Any annotations, edits, or processing should be done in the JSON file located in the `Vault` directory.  

## Project Goal

The goal of this project is to build a clear, structured, and expandable database of training targets that can serve as a shared foundation for both human and AI workflows.
